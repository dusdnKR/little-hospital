# Data

## Source and download

The experiments use the multimodal (MM) subset of **TsinghuaC3I/MedXpertQA**, revision `7e7c465a68eb2b866926bfa59c8c9d17a8daba65`.

- [Pinned files](https://huggingface.co/datasets/TsinghuaC3I/MedXpertQA/tree/7e7c465a68eb2b866926bfa59c8c9d17a8daba65)
- [Dataset card and license declaration](https://huggingface.co/datasets/TsinghuaC3I/MedXpertQA/blob/7e7c465a68eb2b866926bfa59c8c9d17a8daba65/README.md)
- [Upstream MIT license](https://github.com/TsinghuaC3I/MedXpertQA/blob/main/LICENSE)

`download-data --download` fetches the card, MM development/test JSONL files and `images.zip` (about 517 MB). `configs/dataset_source.json` pins all four SHA-256 hashes. Existing files are audited, not silently replaced. For an existing snapshot:

```bash
python -m clinical_memory download-data --root /path/to/snapshot
python -m clinical_memory prepare-data --source /path/to/snapshot
```

## Curated inputs and preprocessing

`resources/cohort/` contains the final 336 case files, separate answer keys, speech profiles, fixed difficulty measurements, ordered cohort manifest, deterministic split, and the 168 rewritten opening statements used for augmentation. These are dataset derivatives needed to reproduce the chosen inputs. They are not regenerated by another model invocation during setup.

The clinical file separates public opening text, patient history facts and examination records. Speech profiles contain recorded reviewed or rule-verified utterances; those status fields do **not** imply that every case received independent clinical validation. Selection and rewriting involved prior curation and cannot be recovered from a general text splitter alone. The released snapshot makes that fixed input explicit.

`clinical_memory/data/prepare.py` performs these reproducible steps:

1. Verify source and curated-file hashes and all 336 patient identifiers.
2. Check every answer key against the original source row and verify that collection records contain no answer-option fields.
3. Validate the speech overlay against its exact source case and assign all source images to examinations without duplication or loss.
4. Extract the 418 referenced original images using validated ZIP paths.
5. Materialize `data/processed/cohort`, `data/processed/manifest.json`, and `data/augmented/openings.jsonl` without overwriting changed inputs.
6. Recompute and verify the final split and curriculum order.

The main split uses seed 42. Training randomness uses seeds 42, 43 and 44. Test 1 contains 34 independent patients with a same-disease training partner. Test 2 derives from 168 of the 302 training patients; it is an augmentation/retention evaluation, not an independent-patient generalization set. Difficulty controls training order, not outcome-based selection of the test patients.

## Augmentation

```bash
python -m clinical_memory augment images
python -m clinical_memory augment build
python -m clinical_memory augment check
```

The supplied opening rewrites preserve numbers and meaning. The builder checks their identifiers, lengths and textual similarity. Image transforms use deterministic mild rotation, crop, brightness and contrast changes; images are never flipped. The recipe creates 200 images. The manifest binds each image and patient to its source and hash. Pillow 12.0.0 is pinned; platform-specific PNG compression can change encoded bytes even when pixels are identical. Resume and audit therefore bind to the locally generated image manifest. Do not mix image manifests or resume archived runs with this refactored code.

To prepare a new curated cohort, supply reviewed case/speech files and explicit metadata, then update the experiment's manifest and division hashes. The provided commands reproduce the fixed final cohort and do not claim to automate clinical curation of arbitrary cases.

## Simulation result data and redistribution

The pinned **dataset card itself** declares `license: mit`; the upstream repository supplies the MIT notice. On that published license basis, this distribution includes derived text records and the 21 original images actually returned during the bundled simulation encounters. The copyright and permission notice is preserved in `LICENSES/MedXpertQA-MIT.txt`. No separate restriction is stated for these files in the pinned dataset card.

`resources/replay/` includes all 34 Test 1 encounters per model for the same `key_dx` / random / seed 42 condition (102 encounters), with no outcome filtering. Records retain the complete clinical transcript, reasoning, submitted diagnosis and exact-match score. Source run identifiers, original episode hashes, exported-file hashes and image hashes are recorded in its manifest. These are generated research outputs derived from MedXpertQA; they are not real consultations or new model runs.

Only this defined simulation cohort is included as a result artifact. Full inference logs, trained notebooks and model weights are not needed for playback. Download weights from the pinned model providers under their own terms. Raw downloads, generated data, runs and new reports are ignored by Git; `resources/` holds the explicitly distributed inputs and replay assets.
